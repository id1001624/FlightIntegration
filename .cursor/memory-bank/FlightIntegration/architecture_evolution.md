# 台灣航班整合系統架構演進記錄

## 2025-01-14: 從假數據到真實API的架構轉型

### 背景問題
- 用戶遇到前端目的地機場查詢錯誤，後端Amadeus API返回500錯誤
- 發現TPE不在Amadeus Test API緩存數據中的限制
- 意識到現有架構缺陷：嘗試將實時API數據映射到靜態航班記錄

### 關鍵架構決策

#### 1. 停用有缺陷的同步腳本
- **移除**: `sync_amadeus_prices.py` 
- **原因**: 試圖將實時API數據強制映射到靜態數據庫記錄
- **問題**: 大量"未找到對應航班"警告，1500次API調用效率低下

#### 2. 重新定義 ticket_price 表用途
- **舊用途**: 實時價格存儲
- **新用途**: 價格歷史/趨勢分析 + 短期緩存
- **新增欄位**: `is_cached`, `cache_expires_at`, `search_key`, `origin_airport_code`, `destination_airport_code`, `departure_date`, `cabin_class`

#### 3. 創建實時價格服務架構
- **新服務**: `realtime_price_service.py`
- **核心功能**: 實時查詢 + 智能緩存
- **緩存策略**: 4小時過期，按需緩存，支持價格歷史

#### 4. 混合查詢策略
- **優先級**: 實時Amadeus API → 緩存數據 → 靜態數據庫
- **實現位置**: `flight_controller.py`
- **用戶體驗**: 零感知降級，始終獲得最佳可用數據

### 數據庫模型適配性確認
- **Airline**: `airline_id` ↔ `carrierCode` ✅
- **Airport**: `airport_id` ↔ `iataCode` ✅  
- **Flight**: 字段完全匹配 ✅
- **TicketPrice**: 四種艙等完全對應 ✅

### 技術債務清理
- 刪除 `generate_fake_prices.py` - 假數據生成腳本
- 刪除 `flights_tpe_nrt_2025-04-12.json` - 舊格式測試數據
- 修復所有linter錯誤：類型註解、導入問題、API調用參數

### 緩存架構對比

#### 目的地緩存（已實現）
- 靜態路線關係數據
- 定期同步更新
- 零延遲查詢體驗

#### 價格緩存（新實現）  
- 動態價格數據

兩種架構遵循相同核心概念：分層緩存、降級策略、用戶體驗優先、成本效益。
