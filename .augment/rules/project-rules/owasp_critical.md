## OWASP 關鍵安全規則

本文檔提供基於 OWASP Top 10 的關鍵安全規則，用於指導安全開發實踐。

### 身份驗證與授權

- **密碼策略**:
  - 強制密碼複雜度: 至少8個字符，包含大小寫字母、數字和符號
  - 實現帳戶鎖定機制: 連續5次登入失敗後鎖定30分鐘
  - 使用 Argon2id 或 PBKDF2 算法進行密碼哈希，絕不存儲明文密碼

- **JWT安全實踐**:
  - 使用 RS256 等非對稱簽名算法
  - 設置合理的令牌有效期 (短會話: 15分鐘)
  - 不在 JWT 中存儲敏感數據

- **授權控制**:
  - 在所有敏感操作前強制檢查用戶權限
  - 使用基於角色的訪問控制 (RBAC)
  - 遵循最小權限原則

### 輸入驗證與注入防護

- **輸入驗證**:
  - 對所有用戶輸入進行驗證和淨化
  - 使用白名單策略而非黑名單策略
  - 服務器端驗證不可被繞過

- **SQL注入防護**:
  - 使用參數化查詢或 ORM
  - 避免直接拼接 SQL 字符串
  - 限制數據庫帳戶權限

- **XSS防護**:
  - 對輸出到頁面的內容進行適當編碼
  - 實施內容安全策略 (CSP)
  - 在前端框架中避免不安全的 HTML 插入

### 安全通訊與數據保護

- **TLS實施**:
  - 強制使用 TLS 1.2 以上版本
  - 實施 HTTP 嚴格傳輸安全 (HSTS)
  - 僅使用強密碼套件

- **敏感數據保護**:
  - 識別並加密存儲的敏感數據
  - 實施數據最小化原則，僅收集必要信息
  - 正確管理加密密鑰

- **CSRF防護**:
  - 為所有修改操作的表單添加 CSRF 令牌
  - 對 API 請求使用自定義請求頭或令牌
  - 驗證 Origin 和 Referer 頭部

### 安全配置與錯誤處理

- **安全配置**:
  - 使用環境變量存儲機密信息
  - 禁用不必要的功能、端口和服務
  - 確保生產環境中沒有調試功能

- **錯誤處理**:
  - 實施自定義錯誤頁面
  - 避免向用戶展示詳細的錯誤信息
  - 安全地記錄錯誤，不暴露敏感數據

- **依賴管理**:
  - 定期更新所有依賴庫
  - 使用自動化工具檢查依賴的安全漏洞
  - 明確指定依賴版本

### API 安全

- **API 保護**:
  - 實施速率限制防止濫用
  - 使用 OAuth 2.0 或 JWT 進行身份驗證
  - 驗證所有 API 參數

- **文件上傳安全**:
  - 嚴格驗證文件類型、大小和內容
  - 將上傳的文件存儲在非可執行目錄
  - 生成隨機文件名，避免路徑遍歷攻擊

## 基本安全開發流程

- 在開發初期進行威脅建模
- 實施持續的安全測試
- 將安全代碼審查納入開發流程
- 遵循「安全默認」原則設計系統
