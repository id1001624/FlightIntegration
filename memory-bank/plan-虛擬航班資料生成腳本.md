# 虛擬航班資料生成腳本計畫

## 需求分析
- **核心需求**:
  - [ ] 創建一個新的 Python 腳本 (`generate_dummy_flight_data.py`) 用於生成虛擬航班資料。
  - [ ] 生成的資料應主要模擬從台灣機場 (`TAIWAN_AIRPORTS` in `constants.py`) 出發的航班。
  - [ ] 生成的資料應主要模擬目標航空公司 (`TARGET_AIRLINES` in `constants.py`) 的航班。
  - [ ] 生成的資料應包含 `flights` 表所需的主要欄位（航班號、起降機場、計畫/實際時間、狀態等）。
  - [ ] 生成的資料應具有一定的隨機性和真實感（例如，航班號格式、時間分佈）。
  - [ ] 腳本應能將生成的虛擬資料導入到 PostgreSQL 資料庫的 `flights` 表中。
  - [ ] 腳本應提供配置選項，例如要生成的天數、每天航班的大致數量等。
  - [ ] 腳本旨在替代 `sync_flight_data.py` 在開發/測試階段使用，以避免消耗 API 配額。

- **技術限制**:
  - [ ] 使用 Python 3。
  - [ ] 依賴現有的資料庫連接設定 (`DbManager` 或直接使用 SQLAlchemy/psycopg2)。
  - [ ] 生成的資料模式需與 `flights` 表結構一致。
  - [ ] 應與 `constants.py` 中的機場和航空公司列表保持同步。

## 組件分析
- **受影響的組件**:
  - **新腳本**: `backend/app/scripts/generate_dummy_flight_data.py` (創建)
    - 變更需求: 實現數據生成和導入邏輯。
    - 依賴關係: `constants.py`, `DbManager` (或直接 DB 連接), `models` (如果使用 ORM)。
  - **DbManager** (`backend/app/scripts/db_manager.py`):
    - 變更需求: 可能需要微調或複用其插入邏輯，確保與虛擬數據兼容。
    - 依賴關係: 資料庫連接, SQLAlchemy 模型。
  - **constants.py** (`backend/app/scripts/constants.py`):
    - 變更需求: 無，但腳本會讀取此文件中的 `TAIWAN_AIRPORTS` 和 `TARGET_AIRLINES`。
    - 依賴關係: 無。
  - **資料庫**: `flights` 表
    - 變更需求: 將被插入大量虛擬數據。
    - 依賴關係: 無。

## 設計決策
- **架構**:
  - [ ] 創建一個獨立的、可通過命令行運行的 Python 腳本。
  - [ ] 利用 `argparse` 處理命令行參數（如生成天數、數量、起始日期）。
  - [ ] 腳本內部邏輯分為：參數解析 -> 數據生成 -> 資料庫導入。
  - [ ] 考慮使用如 `Faker` 庫來生成更真實的隨機數據（航班號、時間等）。

- **資料生成**:
  - [ ] 航班號生成邏輯：結合航空公司代碼和隨機數字。
  - [ ] 時間生成邏輯：在指定日期範圍內生成合理的起降時間，並模擬一些延誤。
  - [ ] 機場選擇：主要從 `TAIWAN_AIRPORTS` 中隨機選擇出發機場，從其他機場隨機選擇到達機場。
  - [ ] 航空公司選擇：主要從 `TARGET_AIRLINES` 中隨機選擇。
  - [ ] 狀態生成：模擬不同的航班狀態（準時、延誤、取消等）。

- **資料庫導入**:
  - [ ] 複用 `DbManager` 中的批量插入邏輯（如果適用且高效）。
  - [ ] 或者直接使用 SQLAlchemy Core API 或 `psycopg2` 進行高效的批量 `INSERT`。
  - [ ] 在導入前可能需要檢查或清空現有數據（作為選項）。
