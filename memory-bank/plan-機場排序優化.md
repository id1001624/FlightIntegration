# 優化起飛機場排序計畫

## 需求分析
- **核心需求**:
  - [ ] 根據可用航班數量對台灣機場進行排序
  - [ ] 在 `AirportSelector` 元件中顯示排序後的機場列表
  - [ ] 確保台灣主要機場（如桃園、松山）顯示在前面
  - [ ] 維持其他地區機場的現有分類和排序邏輯
  - [ ] 優化用戶選擇機場的體驗

- **技術限制**:
  - [ ] 需與現有的機場分類邏輯整合（按國家和地區分類）
  - [ ] 需與現有的 `AirportSelector` 元件整合
  - [ ] 應高效處理機場資料，避免不必要的計算

## 組件分析
- **受影響的組件**:
  - **機場資料服務**:
    - 變更需求: 需要添加計算每個機場航班數量的邏輯
    - 依賴關係: 依賴航班資料和機場資料

  - **AirportSelector 元件**:
    - 變更需求: 修改排序邏輯以支持按航班數量排序
    - 依賴關係: 依賴機場資料服務

  - **機場分類邏輯**:
    - 變更需求: 需要保持按地區分類的同時實現台灣機場的特殊排序
    - 依賴關係: 依賴機場資料結構

## 設計決策
- **架構**:
  - [ ] 在現有的機場資料處理服務中添加航班數量統計邏輯
  - [ ] 使用快取策略減少重複計算
  - [ ] 設計彈性的排序策略，可根據不同條件排序

- **演算法**:
  - [ ] 使用機場代碼與航班數量的映射結構存儲排序依據
  - [ ] 實現複合排序策略：先按地區分類，再按航班數量排序
  - [ ] 考慮添加優先級因子，確保主要機場優先顯示
