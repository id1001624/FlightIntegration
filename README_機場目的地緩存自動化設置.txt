# 機場目的地緩存自動化設置說明

本文件說明如何設置機場目的地緩存的自動同步，解決前端選擇目的地時的 API 延遲問題。

## 背景說明

我們已經實施了機場目的地緩存系統：
- 前端延遲從 21-23 秒降低到 < 1 秒
- 緩存數據需要定期從 Amadeus API 同步更新
- 建議每天同步一次以保持數據時效性

## 可用的自動化選項

### 選項 1：手動執行 （即時同步）

雙擊執行：
```
auto_sync_destinations.bat
```

特點：
- 立即執行同步
- 可以看到詳細的執行過程
- 適合測試或臨時更新

### 選項 2：一次性定時執行 （今晚自動）

雙擊執行：
```
auto_sync_destinations_tonight.bat
```

特點：
- 設置今晚凌晨 1:30 自動執行
- 一次性任務，執行完畢後不會重複
- 適合快速建立今晚的同步任務

### 選項 3：設置定期自動執行 （推薦）

使用 Windows 排程任務設置每日自動同步：

#### 3.1 開啟工作排程器

- 按 `Win + R` 開啟執行對話框
- 輸入 `taskschd.msc` 並按確定
- 工作排程器視窗將會開啟

#### 3.2 創建新的排程任務

- 在右側操作面板中點選「建立基本工作...」
- 輸入任務名稱：`機場目的地緩存自動同步`
- 輸入描述：`每日同步機場目的地緩存數據，提升前端響應速度`
- 點選「下一步」

#### 3.3 設定任務觸發條件

- 選擇「每天」，點選「下一步」
- 設定開始時間：`01:30:00`（建議選擇系統使用率較低的時間）
- 點選「下一步」

#### 3.4 設定動作

- 選擇「啟動程式」，點選「下一步」
- 在「程式或指令碼」欄位中，輸入：
  ```
  C:\Users\Aliothouo\OneDrive\文件\學校\AlphaVision\FlightIntegration\auto_sync_destinations.bat
  ```
- 在「新增引數」欄位中，輸入：`silent`
- 在「起始於」欄位中，輸入：
  ```
  C:\Users\Aliothouo\OneDrive\文件\學校\AlphaVision\FlightIntegration
  ```
- 點選「下一步」

#### 3.5 完成設定

- 勾選「當按一下『完成』時，開啟此工作屬性對話方塊」
- 點選「完成」

#### 3.6 進階設定

在開啟的屬性對話方塊中：

- **「一般」標籤**：
  - 勾選「不管使用者是否登入都執行」選項
  - 勾選「以最高權限執行」
  
- **「設定」標籤**：
  - 勾選「如果工作執行超過以下時間，則停止工作」，設為 30 分鐘
  - 勾選「如果工作失敗，每隔以下時間重新開始」，設為 1 小時，最多重試 3 次
  
- 點選「確定」儲存設定

## 測試排程任務

建立任務後，可以在工作排程器中手動測試：

1. 找到剛建立的任務「機場目的地緩存自動同步」
2. 右鍵點選該任務
3. 選擇「執行」
4. 確認同步操作是否成功執行

## 監控與日誌

### 日誌位置
- 執行日誌：`backend\sync_destinations_log.txt`
- 應用日誌：`backend\logs\`

### 檢查同步結果
可以通過以下方式確認同步是否成功：

1. **檢查 API 響應**：
   - 測試 `GET /api/airports/TPE/destinations-cached`
   - 確認返回數據數量是否合理

2. **檢查數據庫**：
   - 查看 `airport_destinations` 表的記錄數量
   - 確認 `last_synced_at` 時間戳是否更新

3. **檢查日誌文件**：
   - 查看同步過程是否有錯誤
   - 確認同步的機場和目的地數量

## 排程任務設置建議

- **執行頻率**：每天執行一次（足以保持數據時效性）
- **執行時間**：凌晨 1:30（避開系統高負載時段，且早於其他數據同步任務）
- **重試機制**：設置失敗重試，確保數據同步的可靠性
- **超時設置**：30 分鐘足以完成所有台灣機場的同步

## 注意事項

### 網路與 API 需求
1. 確保執行時網路連接正常
2. 檢查 Amadeus API 憑證是否有效且未過期
3. 避免在 API 維護時段執行

### 系統資源
1. 同步過程會消耗一定的 CPU 和網路資源
2. 資料庫寫入操作較多，建議在低負載時段執行
3. 確保有足夠的磁碟空間存儲日誌文件

### 備份建議
1. 定期備份 `airport_destinations` 表數據
2. 保留重要的同步日誌文件
3. 建議設置資料庫的定期備份機制

## 故障排除

### 常見問題

**問題 1：同步失敗，錯誤代碼非零**
- 解決方案：檢查網路連接和 API 憑證，查看詳細日誌

**問題 2：部分機場同步失敗**
- 解決方案：檢查特定機場的 IATA 代碼是否正確，API 是否支援該機場

**問題 3：排程任務未執行**
- 解決方案：確認任務設置正確，檢查用戶權限和系統時間

### 日誌排查
若同步失敗，請按以下順序檢查：

1. `sync_destinations_log.txt` - 同步腳本的直接輸出
2. `backend\logs\` - 應用程式詳細日誌
3. Windows 事件檢視器 - 系統層級的錯誤信息

## 效果驗證

設置自動同步後，您應該能體驗到：

1. **前端響應速度**：目的地選擇從 20+ 秒變為 < 1 秒
2. **數據準確性**：緩存數據每日更新，保持與 Amadeus 一致
3. **系統穩定性**：即使 Amadeus API 暫時不可用，緩存仍可提供服務

若有問題，請聯繫開發團隊或查閱完整的錯誤日誌進行進一步排除。
